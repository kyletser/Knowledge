## 公众号订阅集成进研途助手个人网站（peronalsite）
**用户决策变化：** Kyle 提出「那我没运行你，你的自动化也运行不了啊」+「前端页面你自己设计好和我讨论功能」+ 提供腾讯云服务器凭据 → 拒绝另起站，要求把公众号订阅做进现有 `kyletser/peronalsite`（Docker Compose + FastAPI + React/TS/Vite/Tailwind + SQLite）。

**架构决策：加模块，不另起容器**
理由：peronalsite 24h 在线 + 持久卷 + 密码登录 + 路由框架，「不依赖我也能自动跑」全部前提已满足。

**新增文件（实际代码改动）：**
- 后端：`backend/app/wechat_parser.py`（移植自 Knowledge/AI/.tools/wechat_archive.py + sync.py 的软断行，零图门槛，限流不重试）、`wechat_detector.py`（RSS 2.0/Atom + URL 归一化 + 时间窗，兼容 we-mp-rss/WeWe-RSS/RSSHub）、`scheduler.py`（APScheduler AsyncIOScheduler + 固定 UTC 偏移，不依赖系统 tzdata）、`wechat_sync.py`（检测→去重→抓取→入库流水线 + 并发锁 + 限流停手）、`routers/wechat.py`（账号/文章/状态/同步/inbox RESTful）。
- 前端：`frontend/src/pages/WeChat.tsx`（状态卡 + 账号侧栏 + 全部/未读/已收藏筛选 + 搜索 + 抽屉式阅读器 react-markdown）+ `services/api.ts` 加 8 个方法 + 6 个类型。
- 部署：`.env.example` 加 8 个 WECHAT_* 开关；`README.md` 加订阅使用说明。

**关键设计点：**
1. 账号 `feed_url` 为空 = 仅手动投喂模式 → 默认零配置可用，不依赖外部检测源。
2. 同一账号下，`WECHAT_DETECTOR_BASE_URL` + 账号 `feed_id` → 自动拼 we-mp-rss 风格 URL，账号只需填短 ID。
3. 图片挂 `/media/wechat/<article_id>/<file>` 公开路径，加入 auth_middleware 白名单，避免 `<img>` 携带 Bearer token 的痛点。
4. 限流单次即止（沿用 Knowledge 仓库「少抓几次」原则）。
5. 保存门槛默认 1 张图（沿用 Knowledge 仓库铁律），`WECHAT_MIN_IMAGES=0` 可放行纯文字。

**部署踩坑：**
- lucide-react 0.562.0 不带 d.ts 但 package.json typings 字段写了 → npm install 不完整时 tsc -b --force 会炸。重装 lucide-react 自动恢复。
- DATA_ROOT 最初用 `os.path.join()` 返回 str，被 `cleanup_article(data_root: Path)` 拒绝 → 改 `pathlib.Path(DATA_DIR) / "wechat"`。
- 服务器端 `deploy.cmd` 依赖本机 `.agents/ssh-askpass.local.cmd`（密码助手）→ 改用 paramiko 串 SSH 自行做：bundle 上传 + 部署脚本上传 + 跑 `deploy-server.sh`。
- paramiko 5.x `get_pty=True` 时 stdout.readline 返回 str 而非 bytes，要 print 而不是 decode。
