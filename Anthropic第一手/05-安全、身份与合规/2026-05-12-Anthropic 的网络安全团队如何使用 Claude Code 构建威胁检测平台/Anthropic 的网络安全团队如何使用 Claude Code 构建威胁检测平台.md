Jackie Bow 是 Anthropic 检测平台工程团队的技术负责人，她讲述了团队如何用 Claude Code 构建工具，把警报分类自动化、加速调查，并改变安全分析师的工作方式。

在 Jackie Bow 的整个职业生涯里，她一直设想着这样一种工具：它能挖掘真正关键的上下文——不只是日志和警报，还包括 Slack 对话、内部文档和机构知识，这些东西能告诉你某件事究竟是真实威胁还是只是噪声——而不需要人类承担手动梳理数据的重担。

当她加入 Anthropic 时，终于有机会与 Claude 一起把它们造出来。Jackie 领导的检测平台工程团队专注于防御性网络安全：检测威胁、对潜在的违规事件做出响应，而不是去探测漏洞。这项工作包括监控系统是否存在可疑活动、对安全警报做分类，以及在异常演变成事件之前就展开调查。

对一家能力不断增强的 AI 模型公司而言，这项工作至关重要。 [Anthropic 的负责任扩展政策](https://www.anthropic.com/news/anthropics-responsible-scaling-policy) 把产品发布与安全承诺直接挂钩，这意味着 Bow 的团队能帮公司决定哪些产品可以安全地交付。

「我觉得这简直是安全工程师的黄金时代，」身兼 Anthropic 检测平台工程团队技术负责人的 Bow 说，「我终于能造出那些我一直想要、却求而不得的工具了。」

## 问题：淹没在数据和警报中

安全负责人对这种模式再熟悉不过了。

警报响起。分析师打开终端，开始那套熟悉的仪式——在五六个不同工具之间来回跳转，每个工具都要用自己的查询语言和心智模型。他们必须在多个平台上保持专业能力，同时不断在不同界面和查询语法之间切换上下文。

每一次调查都成了一场数据考古，要把散落在互不连通系统里的碎片拼凑起来。对大多数团队来说，简单的调查要花上几个小时，复杂的则可能拖上好几天。

「一个人一天能看的警报就那么多，再往后，他钻进去的细致程度就开始直线下降，」Jackie 解释道。

她的团队决定做点什么。他们问自己：是什么在消耗我们的精力？什么让人觉得重复？是什么阻碍了真正有价值的工作？

答案很清楚。在分析师能判断威胁是否真实之前，光是警报分类就可能耗掉好几个小时。跨互不连通系统的手动关联拖慢了一切。而查询语言和界面之间不断的上下文切换，制造出会在一整天里不断累积的认知负担。

随着公司成长，攻击面在扩大，对安全团队的要求也在提高。

「如果不靠 Claude 这类东西来增强，我们根本无法扩展以满足 Anthropic 的需求，」Jackie 说。

## 解决方案：Claude 去取证（CLUE）

几个月的时间里，Bow 的团队打造了 CLUE——一个重新定义了安全团队调查威胁方式的检测与响应平台。CLUE 没有在既有技术栈上再叠一个仪表盘，而是提供了一个由 Claude 驱动的自然语言界面，通过工具调用直接连到 Anthropic 的内部系统。

用 Claude Code 构建 CLUE，让传统软件开发的时间线呈指数级压缩，使他们能在处理日常工作的同时，腾出手来造出这套系统。Bow 的团队只用一天就跑通了一个概念验证。设计文档、开发步骤和实现在一周内完成。

「我们造的大部分东西，都是在对着 Claude Code 说话，」Jackie 回忆道，「它既是个设计伙伴，也是个协作者。」

真正转变她看法的，是那次她让 Claude Code 在 CLUE 界面上加一个按钮。她本以为又要经历熟悉的苦差事：JavaScript 框架、CSS 调试。结果 Claude Code 立刻就实现了这个功能，而且做得比她更好。

「那一刻我意识到，我不再受自己技术水平的束缚了。只要我想得到，我就能造得出来，」她说。

### CLUE 分类（CLUE Triage）

警报涌入时，CLUE 分类会在人类分析师看到它们之前，先完成第一轮初查。Claude 通过工具，用来自 Anthropic 各系统的额外上下文来丰富每一条警报，包括 Slack 消息、内部文档、代码仓库和数据仓库。它会给出处置结论：假阳性、真阳性、恶意，或是预期行为。每条警报还会得到一个置信度分数，让分析师知道该把注意力放在哪里。

这个丰富化步骤解决了一个所有安全分析师都认得的问题：警报是作为孤立信号到达的。一次失败的登录尝试。一个反常的 API 调用。一次配置变更。没有上下文，这些事件就只是噪声。有了上下文（这个用户是谁、在做什么、是否符合其团队的模式），清晰的信息就浮现出来了。

「内部上下文，正是那个能让警报贴合你们自身环境、被恰当语境化的缺失拼图，」Jackie 解释道。

### CLUE 调查（CLUE Investigate）

有了 CLUE，安全分析师现在可以用自然语言查询所有安全关键日志。想知道「这个系统过去一天里所有失败的登录有哪些？」只需问问 CLUE，Claude 就会执行必要的 SQL 查询。

「Claude 写精确查询的能力比人类强得多，」Jackie 说。这个工具跑的是一个智能体式循环：协调器向子代理发出指令，子代理并行执行查询、收集发现，并把结果综合成一份连贯的调查摘要。原本需要数小时手动关联的工作，现在三到四分钟就能跑完。

数字印证了这一点。在各类调查中，CLUE 平均每次会话有 25 次工具调用和近 11 次查询——远超分析师合理手动执行的数量，而且精度更高。否则，每一次工具调用都得另开一个控制台，或切到另一个界面。

然而，真正的差异化优势在于内部上下文。CLUE 通过工具直连 Anthropic 的系统，让 Claude 得以访问外部安全平台永远接触不到的机构知识。警报触发时，Claude 可以查 Slack，看团队是否在讨论计划内的维护；可以查数据仓库，了解基线行为；可以查代码仓库，弄清某个服务到底在干什么。

### 数据治理审查

团队用一个常见的数据治理场景演示了 CLUE 的能力：检查三名承包商在过去两个月里，是否访问过任何本不该访问的文档。

据 Bow 说，这类调查通常至少要半天的手动工作，包括查询访问日志、交叉比对权限、审查文档密级。有了 CLUE，Claude 读取请求、制定计划，并生成把技术复杂性抽象掉的详尽查询。调查在几分钟内结束，产出一份摘要和建议，而且对每次执行的查询都完全透明。

## 衡量影响

团队着手构建 CLUE 时，不光想知道「感觉是不是更快了」，更想搞清楚能不能把结果量化。

**更少的假阳性**：在 CLUE 分类之前，大约三分之一的警报最终被证明是假阳性。这个比例已经降到 7%，意味着分析师把时间花在了真正重要的信号上。\*

**更广的覆盖**：也许比速度更重要的是团队现在能审查的东西。在 CLUE 之前，低置信度的信号因为根本没有时间，根本无人审查。如今，CLUE 分类会对每一条入站警报都做带丰富化的处理，批处理则能消化此前在仪表盘里只是噪声的成千上万个信号。

**大规模节省时间**：根据 30 天的使用情况，CLUE 自动化执行了约 12,000 次查询和 27,000 次工具调用——如果手动完成，估计需要 1,870 小时（234 人天）。相比手动分类，这意味着 5–10 倍的提速。\*

**仍在摸索度量什么**：准确度比速度更难量化。团队会复核 CLUE 的处置结论、追踪分歧，但他们仍在构建反馈回路，以了解 Claude 抓住分析师可能漏掉的东西的频率，反之亦然。笔录帮了大忙：每一次调查都可以被审计，确切地看清 Claude 查了什么、又是怎么得出结论的。

## 我们的前进方向：让 Claude 像 Claude 那样去调查

AI 研究里有个概念叫「[惨痛的教训](http://www.incompleteideas.net/IncIdeas/BitterLesson.html)」——它的观察是：把人类特有的推理写死进模型里，始终不如赋予模型通用能力、让它自己找到方法。Bow 和她的团队一直在思考这对检测与响应意味着什么。

「在 CLUE 开发的早期，团队争论过该在多大程度上约束 Claude 的调查路径，」Bow 说，「SOAR 时代的本能是：建剧本、定义每一步、让流程确定性地走完。但我们一直注意到一件事。当我们给 Claude 探索的自由度时（给它工具和目标，而不是死板的顺序），它常常会走我们绝不会指定的调查路径。有时，这些路径会带出我们会错过的上下文。」

关键在于给 Claude 划定边界（能用什么工具、能访问什么数据），同时把策略留开放。这一洞见决定了 CLUE 接下来的走向。

**从被动到主动**：今天，CLUE 是对警报做出响应。事件触发，Claude 去调查。但这套架构也支撑得起更宏大的东西：持续探索。Claude 智能体可以主动搜寻可疑模式——那些不匹配团队写下的任何规则、单独看正常、合起来却反常的行为——而不是等检测规则来触发。

**向自身学习**：团队把每一份调查笔录都存下来。这份语料正变成一个知识库，Claude 可以从中查询过往调查是如何展开的。久而久之，CLUE 会形成人类分析师无法维系的机构记忆。

**拥抱非确定性**：传统安全工具把不一致当成 bug。CLUE 把它当成特性。同一条警报在不同日子可能得到不同的调查——这没关系，有时第二条路径会找出第一条漏掉的东西。团队正在尝试并行跑多种调查策略，再比较结果。

「安全运营的惨痛教训？我们花了好多年去构建把人类调查方式写死进去的系统。下一代工具应该赋予模型调查的能力，让它们找到比我们规定的更好的方法，」Bow 补充道。
