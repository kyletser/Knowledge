# 像新开发者一样入职 Claude Code：17 年开发的经验教训

那套用于把新开发者引入 MacCoss 实验室 70 万行代码库的方法，在 Claude Code 上同样适用。下面是 Brendan MacLean 的做法——他是 Claude 开发者大使，其所在的实验室参与了我们的 [Claude for Open Source](https://claude.com/contact-sales/claude-for-oss) 计划。

[Skyline](https://skyline.ms/home/software/Skyline/wiki-page.view?name=team) 是华盛顿大学 MacCoss 实验室首席开发者 Brendan MacLean 维护的开源蛋白质分析软件，自 2008 年起持续活跃开发中。Skyline 帮助研究人员检测和量化血液、组织等物质中的蛋白质，这对生物标志物发现、疾病研究和药物开发至关重要。MacCoss 实验室的代码库包含 70 多万行 C#，由一个运行 20 多万个夜间自动化测试的小团队维护了 17 年。

![](images/220c23e267f0-69ef9d6a1af11e710950d666-e16f087b.png)

*一幅在 Blender 中创建的西雅图天际线 3D 插图，代表华盛顿大学 MacCoss 实验室的所在地；自 2008 年起，Brendan MacLean 和他的团队一直在那里开发和维护 Skyline。Claude 帮 Brendan 在背面加上了 Claude 徽标。图片由 MacCoss 实验室提供。*

近三十年来，Brendan 一直是 Skyline 的"结缔组织"，将数十名本科生、研究生和博士后带入实验室。*

随着开发人员来了又走，代码库吸收了他们的贡献。到了 2024 年，它背上了长期项目常见的种种负担。随着开发人员更替，某些区域已变得无人敢动。

在数十年培训实验室成员之后，Brendan 很清楚如何让研究人员快速上手实验室庞大的代码库。他没料到的是，同一套方法用在一个 AI 工具上，竟能让 Skyline 的代码库重新变得可管理。

## 同样的入职问题，不同类型的开发者

Brendan 一度怀疑，现代 AI 编码工具能否像那些专为这种语言和环境量身打造的工具那样，真正读懂一行行 C# 代码。

在浏览器中用 Claude.ai 做的早期实验印证了这一模式。他会描述一个问题、得到回复，然后把整个 C# 文件复制回项目，从而把范围限制在那些无需参考项目代码就能描述清楚的、自成一体的问题上。

"一旦改动变得越来越零散，整个过程就变得极其费力，"Brendan 说。

每次使用 Claude.ai 的会话都像是从零开始，因为它根本不了解 Skyline 是什么、各个组件如何关联，也不清楚 17 年开发所沉淀下来的东西。

这正是 Brendan 在给新开发者入职时所面临的体验，这让他萌生了一个想法。

Brendan 说："我可以像带一个实习开发者那样，通过 Claude Code 把 Claude 引入我的大型项目：讲解足够的内容，让它完成一个有限但成功的任务，并为下一次迭代产出更好的上下文。"

他把所有 AI 上下文都移到了一个独立的代码仓库 [pwiz-ai](https://github.com/ProteoWizard/pwiz-ai) 中，与代码库分开存放，这样它就能适用于所有分支和时间点。根目录下的 `CLAUDE.md` 文件负责环境设置，并把 Claude 指向相关文档：把它看作"地形概览"，而不是专业知识本身。

专业知识则存在于[技能](https://agentskills.io/home)中——这是一种用于赋予智能体能力与专业知识的开放格式。例如，他的 `debugging`（调试）技能旨在把 Claude 从他所谓的"猜测—试错"模式中拉出来，在尝试任何修复之前先推动它做根因分析。技能可以手动或自动触发；Brendan 用明确的条件来调校最关键的那几个——`debugging` 技能的描述写着："在排查 bug、故障或异常行为时，始终加载。"

![](images/86ded1feee45-69ef9d6a1af11e710950d669-24e72102.png)

*pwiz-ai 代码仓库的结构，展示了上下文、技能和 MCP 集成如何连接到 Skyline 的代码库。图片由 MacCoss 实验室提供。*

一旦上下文建立起来，教 Claude 摸清代码库调试门道的成本就会显著降低。Claude 已经知道代码在做什么。互动是从理解出发，而不是从零开始。

"Brendan 说："那个曾经看似重大的顾虑——'Claude 没法真正学会我的庞大项目'——如今越来越清晰：上下文不过是需要维护和成长的另一种工件。"

## 减少技术债务、加速开发

Skyline 中有一个历时一年、为构建"文件视图"面板而做的项目——这是一个显示所有文档相关文件的新界面，具备文件系统监控和拖放组织功能——在原负责人离开后一直未能完成。Brendan 用 Claude Code 把它接手了过来。

两周后，面板做完了，所有最终提交都由 Claude 共同署名。

Brendan 说："处于这种状态的前序工作，通常会被丢弃。"在学术实验室里，开发人员流动频繁——研究生毕业、博士后离开、实习生在夏末走人。过去，任何进行中的工作都会永远被束之高阁。

三年前，在失去维护 Skyline 夜间测试管理模块的开发人员后，Brendan 停止为该模块添加功能。该模块用 Java 编写，是 LabKey Server 科学数据门户的一部分。最近，在一位熟练的 LabKey 开发人员用 Claude Code 创建了设置文档之后，Brendan 花了不到一天时间，就加进了他多年来一直想要的功能，并用 CSS 更新了页面布局——而这种 CSS 过去他只雇设计师来做。

新的基础设施随之而来。

Skyline 2000 多张教程截图的复现现在已完全自动化，且几乎 100% 可复现；借助 Claude Code 还扩展出了"仅差异"视图和像素级变化放大，以及一个由 Claude 用 C# 编写的 MCP 服务器，让它能"看见"这些差异。Claude Code 每天早晨会生成一份每日摘要，展示从 Skyline 夜间测试基础设施中提取的测试失败、异常和未关闭的支持工单，在 Brendan 坐下来工作之前就送达他的收件箱。

Claude 还用 Python 编写了实现这一能力的 MCP 服务器，数据来自 LabKey Server 上的三个独立关系数据流、团队邮件，以及 GitHub 上带有发布标签的代码。

![](images/02767a3adfc5-69ef9d6a1af11e710950d66f-29befb00.png)

*一份由 Claude Code 自动生成的每日摘要邮件，从 Skyline 的夜间测试基础设施中提取。图片由 MacCoss 实验室提供。*

Brendan 的开发者们如今自己几乎不写代码，主要改为指导 Claude Code，并让这个工具自主生成自动化脚本和 MCP 实现。例如，实验室里一位原本对智能体式编码工具持怀疑态度的开发者，构建并发布了一个新的绘图扩展——用于可视化离子淌度数据的流动图窗格——并把功劳归于 Claude Code。

Brendan 说："我看到几乎每个人都在尝试有趣的新功能，而这些功能他们以前可能觉得被其他工作埋得太深而不敢动手。"

## 给在遗留代码库上工作的开发者的建议

基于 17 年给开发者入职的经验，以及将同一方法应用于 Claude Code 一年多的实践，以下是 Brendan 想对在遗留代码库上工作的开发者说的话。

**上下文是你最好的朋友**

Claude 生成的待办清单和计划不会跨会话保留。[上下文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)才会保留，而且必须刻意去维护。这正是大多数开发者会跳过的一步，也是大多数开发者的成功止步不前的原因。

Brendan 说："要明白，如果不记录'上下文'，Claude 就没法学。别指望什么魔法。投资去构建并维护你的上下文层。并把它当作任何其他项目工件一样对待：做版本控制、让它成长、持续维护它。"

Brendan 把 AI 上下文放在一个独立的代码仓库里，因为它增长的速度与代码不同，且适用于所有分支和时间点——把它留在代码仓库里正变得愈加受限。把上下文放在同一个仓库里也是一种可行的替代方案；关键在于它要被纳入版本控制、得到维护，并在需要时可随时取用。

**投资建设你的技能库**

用[技能](https://claude.ai/skills)把任何 Claude 实例都能加载的领域知识编码固化下来。Brendan 的技能遵循"引用而非嵌入"的原则：每个技能都指向一个中央文档知识库，而不是重复内容，从而保持轻量、易于维护。

他最常用到的包括：一个 `skyline-development`（Skyline 开发）技能，让 Claude 熟悉项目和其文档；一个 `version-control`（版本控制）技能，固化了项目特定的提交和 PR 约定；以及一个 `debugging`（调试）技能，旨在把 Claude 从"猜测—试错"模式中拉出来，在尝试任何修复之前推动它做根因分析。

**当数据访问是关键时，使用 MCP 集成**

在 Claude 需要访问真实数据的地方构建 [MCP 集成](https://anthropic.com/engineering/mcp)：测试结果、异常报告、支持工单。

对于开源项目而言，构建并维护一个上下文层具有特殊的分量。这里没有入职预算，除了写下来的东西之外也没有机构记忆，更无法保证任何贡献者明年还在。上下文一旦建成，就会对每位贡献者可用，并在项目整个生命周期内持续存在——这是人类机构知识从未做到过的。 `pwiz-ai` 代码仓库本身就是一个开源工件——它属于项目而非任何单个贡献者的上下文，比构建它的每个人都更长久。

## 十七年的入职，一个结论

你不会把一个 70 万行的代码库交给一名新员工，然后指望他第一天就出成果。你会给他找一个自成一体的项目，带着他做一遍，并随着他理解加深而逐步扩大他的职责范围。

正如 Brendan 所领悟到的，你用 Claude 构建的上下文，运作方式如出一辙。

一旦对某个代码库足够了解，工程师就能跨分支、跨时间点地工作。只要给予充分的上下文和方向，Claude 也能做到同样的事。

*Dario Amodei，Anthropic 联合创始人，曾是 MacCoss 实验室的成员。*
