AI 编码工具缩短了想法和工作原型之间的时间。 CodeRabbit 是一个 AI 代码审查平台，它注意到随着吞吐量的增加，出现了一个不同的趋势：编译并通过测试的代码，但没有执行团队实际想要构建的内容。

CodeRabbit 的 AI 副总裁 David Loker 找到了模型上游的原因。有经验的开发人员通常假设编码智能体理解与他们相同的上下文，因此他们不会写下对他们来说显而易见的需求。然后，编码智能体用它认为合理的任何内容来填补空白。

为了弥补这一差距，CodeRabbit 使用 Claude 来设计和构建智能体编排系统，该系统在生成任何代码之前运行结构化规划阶段。该团队的工作论点是，规划质量决定输出质量，代码生成成本越低，朝着错误方向前进的成本就越高。

## **解决 AI 编码中的内部知识差距**

当 CodeRabbit 团队研究 AI 在其客户群中生成的拉取请求时，最常见的故障模式是编译并通过测试的代码，但仍然没有解决其旨在解决的问题。

“当我们作为开发人员获得经验时，我们就会将知识内化，”洛克说。 “所有这些事情都在我们的脑海中，我们假设其他开发人员也知道它们。但是我们也对 AI 系统做出了这样的假设，它也隐含地理解了。我们甚至没有意识到我们正在假设这些事情。”

Vague提示词迫使底层系统用它认为合理的任何东西来填补空白。这种猜测常常与开发人员的想法有所不同。

洛克提供了一个个人例子。在一个业余项目中构建内存系统时，他花了几个小时迭代智能体编码，直到一切正常运行。当他询问智能体如何使用它时，说明告诉他传递一个用户令牌。没有登录页面。他明确指出系统需要用户，但从未说过用户需要一种登录方式。智能体填补了空白，并且在缺少前门的产品中投入了数小时的工作。

“最终发生的情况是你在它上面构建了更多的东西，然后很久以后你发现存在问题，”洛克说。 “在 AI 工作流程中，后期验证的成本可能非常高。”

## **在 AI 编码解决方案之前运行的编排层**

CodeRabbit 的应对措施是在代码生成之前插入一个规划系统。它协调多个 Claude模型来分析需求和表面假设，然后生成结构化执行计划，该计划定义应该构建什么以及需要满足哪些约束。

“这个计划系统并不是要取代 Claude Code 的计划模式，”Loker 说。 “这是在 Claude Code 之前发生的更高级别的编排，将其指向一个非常狭窄且正确的方向，其中需要明确的所有内容都已明确，并且我们知道正在做出的所有假设。”

输出是协作产品需求文档 (PRD)：根据完整上下文创建的计划，由整个团队的利益相关者验证，并在实施开始之前进行审查。 Claude Code 选择该计划并使用它来生成细粒度的实施计划。该计划成为一个共享的工件，捕获所决定的内容和原因，这不仅可以帮助团队避免返工并在以后验证输出是否符合原始意图，而且还可以帮助新工程师加入。

## **跨 Claude模型系列的路由**

CodeRabbit 将每个模型层与任务复杂性相匹配，以优化成本和延迟。 Opus 推动编排循环以及理解问题和设定总体方向的更高级别的战略工作。 Sonnet 获取该输出并将其排序为结构化规划步骤。 Haiku 处理范围狭窄的操作，例如上下文蒸馏和有针对性的工具使用，其中问题足够具体，较小的模型可以很好地回答。

“如果 Haiku 在给定任务上的表现与 Sonnet 一样好，我们就使用 Haiku，”Loker 说。 “如果评估工具告诉我们，当我们给 Opus 更多空间时，计划质量会提高，那么我们就会给它更多空间。我们不会猜测。”

## **构建计划质量评估工具**

CodeRabbit对于代码审查有成熟的评估体系，但对于评估规划输出却没有。建设该基础设施成为了它自己的项目。

该系统从手动调整示例和手动检查开始。该团队开发了一个 LLM 评审库，对计划质量的特定维度进行评分。由于计划最终会生成代码，因此团队还可以衡量生成的代码是否有效、是否包含额外的范围以及需要多少代币才能到达目标。在有或没有计划步骤的情况下运行相同的任务，为他们提供了一种隔离计划本身价值的方法。

“我们没有意识到该计划的详细程度如何，”洛克说。一旦代码库发生变化，过于细化的计划就会变得过时。太高级的计划为智能体留下了填充假设的空间，这是计划层本来要解决的问题。找到抽象的工作级别需要迭代，这就是评估工具使之成为可能的。

## **在编写任何代码之前捕获错误**

在 AI 原生编码工作流程中，过去在代码审查期间出现的许多决策现在都在规划层中提前做出。制定一个可供团队在代码生成开始之前审查和调整的计划，可以及早发现错误。

“我们使用 Claude 生态系统构建了一个团队范围的规划系统，”Loker 说。 “计划本身就成为了一个质量关口。如果我们能够预先确保该计划的质量确实很好，那么下游的效果就会非常明显。最终你会得到更好的代码。”
