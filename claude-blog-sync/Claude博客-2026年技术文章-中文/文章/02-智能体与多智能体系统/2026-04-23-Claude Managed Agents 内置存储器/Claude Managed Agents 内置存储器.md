## Claude 中的内存如何工作 Manged智能体

Claude Managed Agents 的内存是一个内置的、智能优化的内存层，可让智能体从每次会话中学习。内存针对长期运行的智能体的内部基准进行了优化，这些基准在会话之间进行改进并相互分享所学到的知识。

我们发现，当智能体建立在他们已经使用的工具之上时，它的记忆效果最为有效。 Claude Managed Agents 上的内存直接安装到文件系统上，因此 Claude 可以依赖相同的 bash 和代码执行功能，使其在智能体式任务中有效。使用基于文件系统的内存， [我们最新的模型](https://www.anthropic.com/news/claude-opus-4-7#:~:text=Memory.%20Opus%204.7%20is%20better%20at%20using%20file%20system%2Dbased%20memory.%20It%20remembers%20important%20notes%20across%20long%2C%20multi%2Dsession%20work%2C%20and%20uses%20them%20to%20move%20on%20to%20new%20tasks%20that%2C%20as%20a%20result%2C%20need%20less%20up%2Dfront%20context.) 保存更全面、组织良好的记忆，并且对于特定任务要记住的内容更加有洞察力。

## 生产级便携式存储器智能体

内存专为企业部署而构建，具有范围权限、审核日志和完整的编程控制。存储可以在具有不同访问范围的多个智能体之间共享。例如，组织范围的存储可能是只读的，而每用户存储允许读取和写入。多个智能体可以对同一存储同时工作，而不会相互覆盖。

内存是可以通过 API 导出和独立管理的文件，使开发人员能够完全控制。所有更改都会通过详细的审核日志进行跟踪，因此您可以知道内存来自哪个智能体和会话。您可以回滚到早期版本或编辑历史记录中的内容。更新也出现在 [Claude 控制台](https://platform.claude.com/) 作为会话事件，因此开发人员可以跟踪智能体学到了什么以及它来自哪里。

## **正在建设哪些团队**

团队一直在使用内存来关闭反馈循环、加快验证速度并替换自定义检索基础设施：

- **Netflix** 智能体携带跨会话的上下文，包括多次轮流发现的见解以及来自人类对话中的更正，而不是手动更新提示词和技能。
- **乐天的** 基于任务的长时间运行智能体使用内存从每次会话中学习，避免重复过去的错误，将首次通过错误减少 97%，所有这些都在工作区范围内、可观察的边界内。
- **智慧文档** 在托管智能体上构建了文档验证管道，使用跨会话内存来发现和记住重复出现的文档问题，将验证速度提高了 30%。**‍**
- **安藤** 正在托管智能体上构建他们的工作场所消息传递平台，捕获每个组织如何交互，而不是自己构建内存基础设施。
