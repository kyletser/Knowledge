# 通过动态过滤提高网络搜索的准确性和效率

> 发布日期：2026-02-17 · [原文链接](https://claude.com/blog/improved-web-search-with-dynamic-filtering) · 机器翻译，仅供学习。

旁边Claude [Opus 4.6](https://www.anthropic.com/news/claude-opus-4-6) 和 [Sonnet 4.6](https://www.anthropic.com/news/claude-sonnet-4-6)，我们正在发布新版本 [网络搜索](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool) 和 [网络获取](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool) 工具。 Claude 现在可以在 Web 搜索期间本机编写和执行代码，以在结果到达上下文窗口之前对其进行过滤，从而提高其准确性和令牌效率。

## **具有动态过滤的网络搜索**

网络搜索是一项高度令牌密集型的任务。智能体使用基本的网络搜索工具需要进行查询、将搜索结果拉入上下文、从多个网站获取完整的 HTML 文件，并在响应之前对这一切进行推理。但从搜索中提取的上下文通常是不相关的，这会降低响应的质量。

为了提高 Claude 在网络搜索上的性能，我们的网络搜索和网络获取工具现在自动编写和执行代码来后处理查询结果。 Claude 无需对完整 HTML 文件进行推理，而是可以在将搜索结果加载到上下文中之前动态过滤搜索结果，仅保留相关内容并丢弃其余内容。

我们已经 [以前发现的](https://www.anthropic.com/engineering/advanced-tool-use) 该技术在其他智能体式工作流程中有效，并且我们添加了诸如 [代码执行](http://docs.anthropic.com/en/docs/agents-and-tools/tool-use/code-execution-tool) 和 [程序化工具调用](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) 对于我们的 API 的本机支持。我们现在将这些相同的技术引入网络搜索和网络获取。

## **评估 Claude 的网络搜索能力**‍

我们在启用和不启用动态过滤且未启用其他工具的情况下评估了 Sonnet 4.6 和 Opus 4.6 上的网络搜索。在两个基准测试中， [浏览比较](https://cdn.openai.com/pdf/5e10f4ab-d6f7-442e-9508-59515c65e35d/browsecomp.pdf) 和 [深度搜索QA](https://storage.googleapis.com/deepmind-media/DeepSearchQA/DeepSearchQA_benchmark_paper.pdf)，动态过滤将性能平均提高了 11%，同时使用的输入标记减少了 24%。

**BrowseComp：搜索网络以找到一个答案**‍

BrowseComp 测试智能体是否可以浏览许多网站以查找故意难以在网上找到的特定信息。动态滤波显着提高了 Claude 的准确率，使 Sonnet 4.6 从 33.3% 提高到 46.6%，将 Opus 4.6 从 45.3% 提高到 61.6%。
‍

![](images/6ef98367caa4-69937fbbb7eec8e454d86c9d-dynamic-filtering-on-brow.png)

**DeepsearchQA：搜索网络以找到许多答案**‍

DeepsearchQA 向智能体提供具有许多正确答案的研究查询，所有这些都必须通过网络搜索找到。它测试智能体是否可以系统地计划和执行多步骤搜索而不会丢失任何答案。它是通过“F1 分数”来衡量的，它平衡了精确度和召回率，既捕获返回答案的准确性，又捕获搜索的完整性。

动态过滤将 Claude 4.6 的 F1 分数从 52.6% 提高到 59.4%，将 Opus 4.6 的 F1 分数从 69.8% 提高到 77.3%。

![](images/e02df8b2e2d2-69937fcede000ba1d5aab33d-dynamic-filtering-on-deep.png)

令牌成本将根据模型需要写入过滤上下文的代码量而有所不同。 Sonnet 4.6 的价格加权代币在两个基准上均有所下降，但 Opus 4.6 的价格加权代币有所增加。为了更好地了解您自己的成本，我们建议根据您的智能体在生产中可能遇到的一组代表性网络搜索查询来评估此工具。

## 客户聚焦：Quora

[坡](https://poe.com) 通过 [知乎](https://quora.com) 是最大的多模型AI 平台之一，使数百万用户可以通过单个界面访问超过 200 个模型。 Quora 的内部团队发现，具有动态过滤功能的 Opus 4.6“在与其他前沿模型进行测试时，在我们的内部评估中实现了最高的准确度”，产品和研究主管 Gareth Jones 说道。 “模型的行为就像一个真正的研究人员，编写 Python 来解析、过滤和交叉引用结果，而不是在上下文中对原始 HTML 进行推理。*”*

## Web 搜索和获取工具中的动态过滤

当使用我们新的网络搜索和网络获取工具与 Sonnet 4.6 时，动态过滤将默认打开以及 Claude API 上的 Opus 4.6。对于复杂的网络搜索查询，例如筛选技术文档或验证引文，您可以期待与上面显示的类似的性能改进。

以下是在 API 中使用它的方法：

```
{
  "model": "claude-opus-4-6",
  "max_tokens": 4096,
  "tools": [
    {
      "type": "web_search_20260209",
      "name": "web_search"
    },
    {
      "type": "web_fetch_20260209",
      "name": "web_fetch"
    }
  ],
  "messages": [
    {
      "role": "user",
      "content": "Search for the current prices of AAPL and GOOGL, then calculate which has a better P/E ratio."
    }
  ]
}
```

## 代码执行、内存和更多工具现已普遍可用

我们还推出了多种工具，以帮助智能体在代币密集型任务中更好地执行：

- [代码执行](http://docs.anthropic.com/en/docs/agents-and-tools/tool-use/code-execution-tool)**:** 为智能体提供沙箱，以便在对话期间运行代码以过滤上下文、分析数据或执行计算。
- [内存](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)：通过持久文件目录跨对话存储和检索信息，因此智能体可以保留上下文，而无需将所有内容保留在上下文窗口中。
- [编程工具调用](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)**:** 在代码中执行复杂的多工具工作流程，将中间结果保留在上下文窗口之外。
- [工具搜索](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool):从大型库中动态发现工具，无需将所有定义加载到上下文窗口中。[‍](https://platform.claude.com/docs/en/agents-and-tools/tool-use/implement-tool-use#providing-tool-use-examples)
- [工具使用示例](https://platform.claude.com/docs/en/agents-and-tools/tool-use/implement-tool-use#providing-tool-use-examples)**:** 直接在工具定义中提供示例工具调用，以演示使用模式并减少参数错误。
