# 像智能体一样看待：我们如何在 Claude Code 中设计工具

> 发布日期：2026-04-10 · [原文链接](https://claude.com/blog/seeing-like-an-agent) · 机器翻译，仅供学习。

构建智能体线束最困难的部分之一是构建其工具。

Claude 完全通过 [工具调用](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)，但是可以通过多种方式在 Claude API 中使用诸如 [巴什](https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool), [技能](https://code.claude.com/docs/en/skills) 和 [代码执行](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)。 （您可以在 Claude API 上阅读有关编程工具调用的更多信息 [@RLanceMartin 的新文章](https://x.com/RLanceMartin/status/2027450018513490419)).

那么您如何设计智能体的工具呢？您是否为它提供了一种通用工具，例如 bash 或代码执行？或者五十个专用工具，每个用例一个？

想象一下给你一个困难的数学问题。您需要什么工具来解决这个问题？这取决于你自己的技能！

纸张是最少的，但你会受到手动计算的限制。计算器会更好，但您需要知道如何操作更高级的选项。最快、最强大的选择是计算机，但您必须知道如何使用它来编写和执行代码。

这是设计智能体的有用框架。你想为它提供适合其自身能力的工具。但你怎么知道这些能力是什么？你集中注意力，阅读它的输出，进行实验。你学会像智能体一样观察。

如果您正在构建智能体，您将面临与我们相同的问题：何时添加工具、何时删除工具以及如何辨别差异。以下是我们在构建 Claude Code 时如何回答这些问题，包括我们首先出错的地方。

## 使用 AskUserQuestion 工具改进启发

![](images/21c524f66032-69d919d46e9dceaa0cf307d9-b089e3d3.png)

在构建 AskUserQuestion 工具时，我们的目标是提高 Claude 提问的能力（通常称为启发）。

虽然 Claude 只能以纯文本形式提出问题，但我们发现回答这些问题感觉花费了不必要的时间。我们如何减少这种摩擦并增加用户和 Claude 之间的通信带宽？

### 尝试 1：编辑 ExitPlanTool

我们尝试的第一种方法是向 ExitPlanTool 添加一个参数，以便在计划旁边包含一系列问题。这是最容易实施的修复，但它让 Claude 感到困惑，因为我们同时要求制定计划和一系列有关该计划的问题。如果用户的回答与计划所说的相冲突怎么办？ Claude 是否需要调用 ExitPlanTool 两次？我们知道这种策略行不通，所以我们又重新开始。 （您可以阅读更多关于我们为什么制作 ExitPlanTool 的信息 [我们在提示词缓存上的帖子](https://x.com/trq212/status/2024574133011673516))

### 尝试 2：更改输出格式

接下来，我们尝试更新 Claude 的输出指令，以提供稍微修改的 Markdown 格式，可以用来提出问题。例如，我们可以要求它输出一个要点问题列表，并在括号中包含备选方案。然后我们可以解析该问题并将其格式化为用户界面。

Claude 通常可以生成这种格式，但不可靠。它会附加额外的句子、删除选项或完全放弃结构。进入下一个方法。

### 尝试 3：AskUserQuestion 工具

![](images/0e7db4621316-69d919d46e9dceaa0cf307dc-208fceac.png)

最后，我们决定创建一个 Claude 可以随时调用的工具，但在计划模式下特别提示这样做。当工具触发时，我们将显示一个模式来显示问题并阻止智能体的循环，直到用户回答。

该工具允许我们将提示词Claude 进行结构化输出，并帮助我们确保 Claude 为用户提供多种选择。它还为用户提供了编写此功能的方法，例如在 [智能体SDK](https://platform.claude.com/docs/en/agent-sdk/overview) 或在技能中引用它。

最重要的是，Claude 似乎喜欢调用这个工具，我们发现它的输出效果很好。毕竟，如果 Claude 不明白如何调用它，即使设计得最好的工具也无法工作。

这是 Claude Code 中启发的最终形式吗？我们对此表示怀疑。随着 Claude 的功能变得越来越强大，为其提供服务的工具也必须不断发展。下一节将展示一个曾经有帮助的工具开始妨碍的案例。

### 更新功能：任务和待办事项

![](images/86da8eacdf06-69d919d46e9dceaa0cf307df-9f83e911.png)

当我们第一次推出 Claude Code 时，我们意识到模型需要一个 [待办事项清单](https://platform.claude.com/docs/en/agent-sdk/todo-tracking) 以使其保持在正轨上。待办事项可以在开始时编写并在模型工作时进行检查。为此，我们为 Claude 提供了 TodoWrite 工具，该工具可以编写或更新 Todos 并将其显示给用户。

但即便如此，我们也经常看到 Claude 忘记它必须做什么。为了适应这一情况，我们每 5 个回合插入一次系统提醒，提醒 Claude 它的目标。

随着模型的改进，他们发现待办事项列表有限制。当 Claude 意识到需要改变路线时，收到待办事项列表的提醒后，它认为必须坚持该列表而不是对其进行修改。我们还看到 Opus 4.5 在使用子代理方面也变得更好，但是子代理如何在共享待办事项列表上进行协调？

看到这一点，我们将 TodoWrite 功能替换为 [任务工具](https://x.com/trq212/status/2014480496013803643) 。待办事项的重点是让模型保持在正轨上，而任务则帮助智能体相互沟通。任务可以包括依赖项、跨子代理共享更新，并且模型可以更改和删除它们。

随着模型功能的增强，您的模型曾经需要的工具现在可能会限制它们。不断重新审视之前关于需要哪些工具的假设非常重要。这也是为什么坚持使用一小组模型来支持具有相当相似功能配置文件的情况很有用。

## 设计搜索界面

我们构建的最重要的工具是让 Claude 找到自己的上下文的工具。

当 Claude Code 首次在内部发布时，我们使用了 RAG：矢量数据库将对代码库进行预索引，而工具将检索相关片段并在每次响应之前将它们交给 Claude。虽然 RAG 功能强大且快速，但它需要索引和设置，并且在许多不同的环境中可能很脆弱。最重要的是，Claude 是 *给定* 这个上下文而不是寻找上下文本身。

但如果 Claude 可以在网络上搜索，为什么它不能搜索你的代码库呢？通过为 Claude 提供一个 Grep 工具，我们可以让它搜索文件并自行构建上下文。

随着 Claude 变得越来越聪明，如果有合适的工具，它就会越来越擅长构建上下文。

当我们介绍 [智能体技能](https://agentskills.io/home)，我们形式化了渐进式披露的想法，它允许智能体通过探索逐步发现相关上下文。

Claude 现在可以读取技能文件，然后这些文件可以引用模型可以递归读取的其他文件。事实上，技能的常见用途是为 Claude 添加更多搜索功能，例如向其指示如何使用 API 或查询数据库。

在一年的时间里，Claude 从无法真正构建自己的上下文到能够跨多层文件进行嵌套搜索以找到所需的确切上下文。

渐进式披露现在是我们在不添加工具的情况下添加新功能的常用技术。在下一节中，我们将解释原因。

## 渐进披露：Claude Code 指南智能体

Claude Code 目前拥有约 20 个工具，如果我们需要所有这些工具才能使 Claude 发挥最大作用，我们的团队会经常重新访问。添加新工具的门槛很高，因为这为模型提供了多一个需要考虑的选项。

例如，我们注意到Claude对如何使用Claude Code不够了解。如果你问它如何添加 MCP 或斜杠命令的作用，它将无法回复。

我们本可以将所有这些信息放入系统提示词中，但考虑到用户很少询问这一点，这会增加上下文腐烂并干扰 Claude Code 的主要工作：编写代码。

相反，我们尝试了渐进式披露：我们为 Claude 提供了一个指向其文档的链接，它可以在需要时加载和搜索。这确实有效，但 Claude 会将大量文档放入上下文中，以找到用户可以用一句话得到的答案。

因此，我们构建了 Claude Code 指南 - 每当用户询问 Claude Code 本身时，子代理 Claude 就会调用。子代理在自己的上下文中进行文档搜索，遵循有关如何搜索和提取内容的详细说明，然后仅返回答案。主要的智能体的上下文保持干净。

虽然这不是一个完美的解决方案（当您询问 Claude 如何自行设置时，Claude 仍然会感到困惑），但我们能够在不添加新工具的情况下向 Claude 的操作空间添加内容。

### 像智能体一样观察是一门艺术，而不是一门科学

为模型设计工具既是一门艺术，也是一门科学。这在很大程度上取决于您正在使用的模型、智能体的目标及其运行环境。

我们最好的建议是什么？经常实验，阅读你的输出，尝试新事物。最重要的是，尝试像智能体一样看待。
