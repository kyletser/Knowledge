# 将代码审查引入 Claude Code

> 发布日期：2026-03-09 · [原文链接](https://claude.com/blog/code-review) · 机器翻译，仅供学习。

今天我们要介绍的是 Code Review，它会在每个 PR 上派遣一个由智能体组成的团队来发现略过的 bug，这是为了深度而不是速度而构建的。这是我们在 Anthropic 的几乎每个 PR 上运行的系统。现在正在针对团队和企业进行研究预览。

[视频：代码审查简介](https://www.youtube.com/embed/RKsADl0ZC3Y)

## **管理审核瓶颈**

去年，每位 Anthropic 工程师的代码输出增长了 200%。代码审查已成为瓶颈，我们每周都会从客户那里听到同样的情况。他们告诉我们，开发人员捉襟见肘，许多 PR 都是略读而不是深入阅读。

我们需要一位可以信任每个 PR 的审阅者。代码审查的结果是：深入、多智能体审查，发现人类审查者经常错过的错误。这是比我们现有的更彻底（也更昂贵）的选择 [Claude Code GitHub 操作](https://code.claude.com/docs/en/github-actions)，它仍然是开源且可用的。

我们在 Anthropic 上对几乎每个 PR 进行代码审查。之前，16%的PR获得了实质性的审稿意见。现在有 54% 的人这样做。它不会批准 PR（这仍然是人类的呼叫），但它缩小了差距，因此审阅者可以真正覆盖正在发布的内容。

## **它是如何运作的**

当 PR 被打开时，Code Review 会派遣一个智能体团队。智能体并行查找错误、验证错误以过滤掉误报，并按严重性对错误进行排名。结果作为单个高信号概述评论以及针对特定错误的内联评论出现在 PR 上。

评论规模与公关有关。大型或复杂的更改需要更多智能体和更深入的阅读；琐碎的事情会得到轻量级的通过。根据我们的测试，平均审核时间约为 20 分钟。

## **代码审查的实际应用**

我们已经在内部运行了几个月的代码审查：在大型 PR（更改了 1,000 多行）中，84% 的人得到了结果，平均有 7.5 个问题。在 50 行以下的小型 PR 中，这一比例下降至 31%，平均有 0.5 个问题。工程师们基本上同意其表面内容：不到 1% 的发现被标记为不正确。

在一个案例中，对生产服务的单行更改看起来很例行公事，并且是一种通常会得到快速批准的差异。但 Code Review 将其标记为关键。这一更改将破坏服务的身份验证，这是一种很容易在差异中读取的故障模式，但一旦指出就很明显。它在合并之前就被修复了，工程师后来分享说他们自己不会发现这个问题。

抢先体验的客户也看到了类似的模式。上一个 [TrueNAS 开源中间件中的 ZFS 加密重构](https://github.com/truenas/middleware/pull/18291)，代码审查发现了相邻代码中预先存在的错误：类型不匹配，每次同步时都会默默地擦除加密密钥缓存。这是 PR 碰巧触及的代码中的一个潜在问题，扫描变更集的人类审阅者不会立即去寻找这种问题。

## **成本与控制**

代码审查优化了深度，并且比轻量级解决方案（例如 [Claude Code GitHub 操作](https://code.claude.com/docs/en/github-actions)。评论根据代币使用情况计费，一般平均为 15-25 美元，并根据 PR 规模和复杂性进行调整。

管理员有多种方法来控制支出和使用：

- **每月组织上限**：定义所有评论的每月总支出
- **存储库级控制**：仅对您选择的存储库启用评论
- **分析仪表板**：跟踪审查的 PR、接受率和总审查成本

## **开始使用**

代码审查现已作为团队和企业计划的测试版研究预览提供。

- **对于管理员**：在您的中启用代码审查 [Claude Code 设置](http://claude.ai/admin-settings/claude-code)，安装 GitHub 应用程序，然后选择您想要运行评论的存储库。
- **对于开发商**：启用后，评论会自动对新 PR 运行。无需配置。
