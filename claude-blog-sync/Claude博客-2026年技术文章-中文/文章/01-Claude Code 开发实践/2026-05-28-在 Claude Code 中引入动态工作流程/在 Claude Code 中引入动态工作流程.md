# 在 Claude Code 中引入动态工作流程

> 发布日期：2026-05-28 · [原文链接](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code) · 机器翻译，仅供学习。

### **用动态工作流程重写 Bun**

动态工作流程可以大规模解锁的一个例子是最近对 Bun 的重写。 Jarred Sumner 使用动态工作流程将 Bun 从 Zig 移植到 Rust，现有测试套件的 99.8% 通过，大约 750,000 行 Rust，从首次提交到合并仅用了 11 天。一个工作流程为 Zig 代码库中的每个结构体字段映射了正确的 Rust 生命周期。接下来将每个 .rs 文件编写为其 .zig 对应文件的行为相同的端口，数百个智能体与每个文件的两个审阅者并行工作。然后，修复循环驱动构建和测试套件，直到两者都运行干净。港口落地后，连夜的工作流程解决了不必要的数据副本，并为每个副本打开了 PR 进行最终审查。虽然尚未投入生产，但所有这些都是由动态工作流程处理的。贾里德将来会更多地写这方面的文章。

## **它是如何运作的**

当工作流程启动时，Claude 会根据您的提示词进行动态规划，将其分解为子任务，并在并行运行的子代理之间分散工作。结果在合并之前会经过检查，然后您会得到一个统一的答案。智能体从独立的角度解决问题，其他智能体尝试反驳他们的发现，并且运行不断迭代，直到答案收敛 - 这就是工作流程如何达到单遍无法达到的结果。

动态工作流程是为并行且长时间运行的工作而构建的，这些工作可能会持续数小时甚至数天，从而完成以前需要数周时间才能完成的最复杂的工程工作。进度会随着运行的进行而保存，因此被中断的作业会从中断处继续，而不是重新开始。由于协调是在对话之外进行的，因此无论任务有多大，计划都会保持在正轨上。

值得注意的是，动态工作流程比典型的 Claude Code 会话消耗更多的使用量。第一次触发工作流时，Claude Code 会显示将要运行的内容并要求您确认。组织管理员还可以选择通过托管设置禁用工作流程。

## **开始使用**

Max、Team 和 Enterprise 计划以及通过 API 使用 Claude Code 时，动态工作流程默认处于启用状态。专业计划用户可以在 `/config`。要求 Claude 创建工作流程或打开 Claude Code 特定设置 `ultracode` 开始吧。管理员可以管理可用性 [设置](https://code.claude.com/docs/en/settings).

阅读 [文档](https://code.claude.com/docs/en/workflows) 了解更多。
