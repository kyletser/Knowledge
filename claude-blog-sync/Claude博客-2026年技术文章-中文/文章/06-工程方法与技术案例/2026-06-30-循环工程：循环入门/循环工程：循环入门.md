# 循环工程：循环入门

> 发布日期：2026-06-30 · [原文链接](https://claude.com/blog/getting-started-with-loops) · 机器翻译，仅供学习。

## **回合制循环**

![Di](images/f4a29af3203d-6a43eb603762e725a739d98c-8ace2295.png)

- **触发于**：用户提示词。
- **停止标准**：Claude 判断已完成任务或需要额外上下文。
- **最适合用于：** 不属于常规流程或时间表的较短任务。
- **管理使用方式：** 编写具体的提示词并提高验证使用技巧，减少转弯次数。**‍**

您发送的每个提示词都会启动一个手动循环，由您指挥每个回合。 Claude 收集上下文、采取行动、检查其工作、根据需要重复并做出响应。我们将此称为智能体式循环。

例如，要求 Claude 创建一个点赞按钮。它读取您的代码，进行编辑，运行测试，然后返回一些东西 *相信* 作品。然后你手动检查工作，并编写下一个提示词。

您可以通过将手动步骤编码为 SKILL.md 来改进验证步骤，以便 Claude 可以端到端地检查更多自己的工作。 （要在此类自动化的技能、挂钩和子代理之间进行选择，请参阅我们的指南 [转向 Claude Code](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more).)

这应包括允许 Claude 的工具或连接器 *看到*, *测量* 或 *互动* 与结果。检查越定量，Claude就越容易自我验证。

例如，在您的 SKILL.md 文件中您可以指定：

```
---
name: verify-frontend-change
description: Verify any UI change end-to-end before declaring it done.
---

# Verifying frontend changes
Never report a UI change as complete based on a successful edit alone. Verify it the way a human reviewer would:

1. Start the dev server and open the edited page in the browser.

2. Interact with the change directly. For a new control (button, input, toggle): click it, confirm the expected state change, and screenshot before/after.

3. Check the browser console: zero new errors or warnings.

4. Use the Chrome Devtools MCP, run a performance trace and audit Core Web Vitals.

If any step fails, fix the issue and rerun from step 1 — do not hand back partially verified work.
```

## **基于目标的循环 (/goal)**

![](images/50eff79fdcc8-6a43eb603762e725a739d98f-c6fa9ae5.png)

- **触发于**：实时手册提示词。
- **停止标准**：达到目标或达到最大圈数。
- **最适合用于：** 具有可验证退出标准的任务。
- **管理使用方式：** 设置具体的完成标准和明确的周转上限，“尝试 5 次后停止”。

有时，单轮是不够的，特别是对于更复杂的任务。当智能体可以迭代时，他们会做得更好。您可以通过使用 /goal 定义完成的内容来延长 Claude 保持迭代的时间。

当您定义成功标准时，Claude 不必确定什么是“足够好”并提前结束循环。每次 Claude 尝试停止时，评估器模型都会检查您的状况并将其发送回工作状态，直到达到目标或达到您定义的圈数。

这就是为什么确定性标准（例如通过的测试数量或清除某个分数阈值）如此有效。

例如：

```
/goal get the homepage Lighthouse score to 90 or above, stop after 5 tries.
```

## **基于时间的循环（/loop 和 /schedule）**

- **触发于**：指定的时间间隔。
- **停止标准**：您取消它，或者工作完成（PR 合并，队列为空）。
- **最适合用于：** 用于重复性工作，或与外部环境/系统连接。
- **管理使用方式：** 设置更长的间隔或根据事件而不是时间做出反应。

一些智能体式工作是重复出现的：任务保持不变，只有输入发生变化。例如，每天早上总结Slack消息。其他工作取决于外部系统，与外部系统交互的一种简单方法是定期检查它并对发生的变化做出反应。例如，PR 可能会接受代码审查或无法通过 CI。

对于这些，您可以在 Claude 使用“/loop”运行时触发，该循环会按一定时间间隔重新运行提示词。例如：

```
/loop 5m check my PR, address review comments, and fix failing CI
```

`/loop` 在您的计算机上运行，因此如果您将其关闭，它就会停止。您可以通过使用“/schedule”创建例程将循环移至云端。

## **主动循环**

![](images/9b584e751479-6a43eb603762e725a739d989-eb9e496a.png)

- **触发于**：没有实时人员的事件或时间表。
- **停止标准**：每个任务在达到其目标时退出。该例程本身会运行，直到您将其关闭为止。
- **最适合用于：** 明确定义的工作的重复流：错误报告、问题分类、迁移、依赖项升级等。
- **管理使用方式：** 将例程路由到更小、更快的模型并使用功能最强大的模型进行判断调用。

上面的原语以及其他 Claude Code 功能，例如 **自动模式** 和 **动态工作流程** （研究预览）可以组成一个循环以进行长时间运行的工作。

例如，要处理传入的反馈，您可以使用：

1. **`/时间表`** （研究预览）运行检查新报告的例程
2. **`/目标`** 定义完成的内容以及 **技能** 记录如何验证它
3. **动态工作流程** 协调智能体对每个报告进行分类、修复并查看修复情况
4. **自动模式** 所以程序运行时不会停下来请求许可

把它们放在一起，提示词可能看起来像这样：

```
/schedule every hour: check #project-feedback for bug reports. /goal: don't stop until every report found this run is triaged, actioned, and responded to. When fixing a bug, use a workflow to explore three solutions in parallel worktrees and have a judge adversarially review them.
```

## **维护代码质量**

循环输出的质量取决于其周围的系统。设计系统时：

- **保持代码库本身干净**：Claude 遵循代码库中已存在的模式和约定。
- **给Claude一个验证自己工作的方法**：编码对您和您的团队而言良好的外观 [技能](https://code.claude.com/docs/en/skills).
- **使文档易于访问：** 框架和库文档具有最新的最佳实践。
- **使用第二个智能体进行代码审查**：具有新鲜背景的审稿人的偏见较小，并且不受主要智能体的推理的影响。您可以使用内置的“/code-review”技能或 [代码审查](https://code.claude.com/docs/en/code-review) 适用于 GitHub。

当单个结果不符合标准时，不要停留在解决单个问题上，尝试对其进行编码以改进系统以适应未来的所有迭代。

## **管理令牌使用**

为了管理令牌的使用，循环应该有明确的边界：

- **为作业选择正确的原语和模型：** 较小的任务不需要多个智能体或循环。有些任务可以使用更便宜、更快的模型。
- **定义明确的成功和停止标准：** 具体说明完成的内容，以便 Claude 可以更快地找到解决方案（但不会太快）。
- **大规模运行前进行试验：** 动态工作流程可以产生数百个智能体。首先衡量一小部分工作的使用情况。
- **使用脚本进行确定性工作**：运行脚本比通过步骤进行推理要便宜。例如，PDF 技能可以发送 Claude 每次运行的表单填写脚本，而不是重新派生代码。
- **不要更频繁地运行例程：** 将间隔与您正在观看的内容变化的频率相匹配
- **回顾用法：** `/usage` 命令按技能、子代理和 MCP 细分最近的使用情况，不带参数的 `/goal` 显示到目前为止的回合数和令牌使用情况，`/workflows` 显示每个智能体的令牌使用情况，您可以随时停止智能体。

你的 [模型和努力水平](https://claude.com/blog/claude-model-and-effort-level-in-claude-code) 选择是影响循环成本的最大杠杆之一。

## **开始使用**

总结一下：

| 循环 | 你把手放开 | 当 | 伸手去拿 |
| --- | --- | --- | --- |
| 回合制 | 支票 | 您正在探索或决定 | 自定义验证技巧 |
| 基于目标 | 停止条件 | 你知道完成的样子 | `/goal` |
| 基于时间 | 触发器 | 工作按计划在项目之外进行 | `/loop`, `/schedule` |
| 积极主动 | 提示词 | 这项工作是重复性且明确的 | 以上所有以及动态工作流程 |

要开始使用循环，请查看您已经完成的工作。选择一项您遇到瓶颈的任务，并询问您可以移交哪一部分：您可以编写验证检查吗？目标够明确吗？工作是否按计划到达？

一旦你有了一个想法，就运行循环，观察结果，比如它在哪里停止或超出范围，并且不要害怕迭代它。

有关更多信息，请阅读 Claude Code 文档 [并行运行智能体，](https://code.claude.com/docs/en/agents) 以及 [循环](https://code.claude.com/docs/en/goal), [时间表](https://code.claude.com/docs/en/routines), [目标](https://code.claude.com/docs/en/goal), 和 [动态工作流程](https://code.claude.com/docs/en/workflows#orchestrate-subagents-at-scale-with-dynamic-workflows) 页。
