# 集中管理 MCP 连接器的授权

> 发布日期：2026-06-18 · [原文链接](https://claude.com/blog/enterprise-managed-auth) · 机器翻译，仅供学习。

[视频：MCP 连接器的企业管理身份验证](https://www.youtube.com/embed/5kTDt9ewTwE)

管理员现在可以从 Okta 开始，通过身份提供商为整个组织配置 MCP 连接器。用户首次登录时会自动获得连接器访问权限，并由其组织集中配置授权。

连接器使 Claude 在工作中更加有用 - 它们从您的团队已使用的工具中为 Claude 提供所需的上下文。到目前为止，打开它们需要两个步骤：管理员为组织启用连接器，然后每个用户自行授权。

企业管理的授权简化了第二步。管理员授权连接器一次，用户通过他们已有的 IdP 组和角色继承访问权限，并且连接器在有人第一次打开 Claude 时就存在。其结果是为最终用户提供零接触连接器设置。

企业管理的身份验证是该技术的第一个实现 [企业管理授权扩展](https://modelcontextprotocol.io/extensions/auth/enterprise-managed-authorization) 到模型上下文协议。它基于开放标准构建，因此任何连接器都可以支持它 - 包括您自己团队构建的自定义连接器 - 并且它们对于每个 Claude 客户都以相同的方式工作。

### 它是如何运作的

将您的身份提供商连接到 Claude 并选择为您的组织启用哪些 MCP 连接器。当员工登录时，他们的连接器已经存在。 Claude 聊天、Claude Code 和 Cowork 之间的访问保持一致。

对于管理员来说，这会将 MCP 访问管理折叠到管理堆栈其余部分的同一工作流程中：配置一次、按组范围、通过 IdP 管理撤销。由于使用 IdP 检查访问权限是无摩擦的，因此管理员可以缩短访问令牌的生命周期，而不会影响工作效率 - 因此，当有人取消配置时，他们的连接器访问权限会很快过期，而不是停留在旧令牌上。访问通过您已经信任的身份提供商运行，因此连接器与其他所有东西一样受到相同的安全和访问控制，而不是单独的表面来监视。

管理员还可以要求连接器仅通过 IdP 进行连接，这样可以将工作和个人使用完全分开，并防止有人意外地将个人帐户链接到工作工具。

### 建立生态系统

企业管理的授权跨三个组工作：管理访问的身份提供商、支持标准的 MCP 提供商以及跨团队部署托管连接的 Claude 客户。

**身份提供者。** Okta 在发布时就受到支持，并且即将推出对其他身份提供商的支持。

**MCP 提供商。** Asana、Atlassian、Canva、Figma、Granola、Linear 和 Supabase 在发布时就支持企业管理的身份验证，Slack 即将推出。

**Claude 客户。** Hubspot、Ramp 和 Webflow 等组织在其团队中推出了企业管理的身份验证。
