## **问题：淹没在数据和警报中**

安全领导者非常了解这种模式。

警报响起。分析师打开终端，开始在五六个不同工具之间跳转的熟悉仪式，每个工具都需要自己的查询语言和心理模型。他们必须保持跨多个平台的专业知识，同时不断在不同界面和查询语法之间进行上下文切换。

每一次调查都成为数据考古学的一次练习，将分散在断开连接的系统中的碎片拼凑在一起。对于大多数团队来说，简单的调查需要花费数小时，而复杂的调查可能需要数天的时间。

“人们在一天内只能查看这么多警报，然后他们开始了解警报的详细程度，”杰基解释道。

她的团队决定对此做点什么。他们问自己：是什么在消耗我们的能量？什么感觉重复？是什么阻碍我们开展有影响力的工作？

答案很明确。在分析师确定威胁是否真实之前，警报分类可能会耗费数小时的时间。跨断开连接的系统进行手动关联会减慢一切。查询语言和界面之间不断的上下文切换会产生认知开销，并且这种开销会在一天中不断增加。

随着公司的发展，攻击面也在不断扩大，对安全团队的要求也在不断增加。

“如果不使用 Claude 之类的东西进行增强，我们就无法扩展以满足 Anthropic 的需求，”Jackie 说。

## **解决办法：Claude查找证据（CLUE）**

Bow 的团队花了几个月的时间构建了 CLUE，这是一个检测和响应平台，重新构想了安全团队调查威胁的方式。 CLUE 不是在堆栈中添加另一个仪表板，而是提供由 Claude 提供支持的自然语言界面，通过工具使用直接连接到 Anthropic 的内部系统。

使用 Claude Code 构建 CLUE 极大地缩短了传统软件开发时间线，使他们除了处理日常工作之外还可以腾出时间来构建该系统。 Bow 的团队在一天之内就完成了概念验证。设计文档、开发步骤和实施在一周内完成。

“我们构建的大部分内容都是与 Claude Code 对话，”Jackie 回忆道。 “它既是设计伙伴，也是合作者。”

当她要求 Claude Code 在 CLUE 界面添加一个按钮时，她的看法发生了转变。她期待熟悉的 JavaScript 框架和 CSS 调试过程。 Claude Code 立即实现了该功能，并且做得比她更好。

“那时我意识到我不再受自己技术限制的束缚。我可以建造任何我能想到的东西，”她说。

### **线索分类**

当警报涌入时，CLUE Triage 会在人类分析师看到警报之前执行首次筛选。 Claude 使用工具通过 Anthropic 系统的附加上下文来丰富每个警报，包括 Slack 消息、内部文档、代码存储库和数据仓库。它分配处置：误报、真报、恶意或预期行为。每个警报都会收到一个置信度分数，以便分析师知道将注意力集中在哪里。

这一丰富步骤解决了任何安全分析师都认识到的问题：警报作为孤立信号到达。登录尝试失败。不寻常的 API 调用。配置更改。如果没有上下文，这些事件只是噪音。根据上下文（用户是谁、他们正在做什么、这是否符合他们团队的模式），清晰的信号就会出现。

“内部上下文是真正帮助警报根据您的环境进行上下文化的缺失部分，”Jackie 解释道。

### **线索 调查**

借助 CLUE，安全分析师现在可以使用自然语言查询所有安全关键日志。想知道“过去一天该系统登录失败的次数有哪些？”只需询问 CLUE，Claude 就会执行必要的 SQL 查询。

“Claude 比人类更擅长编写精确的查询，”Jackie 说。该工具运行智能体式循环：协调器向子智能体发出命令，子智能体并行执行查询、收集发现并将结果合成为连贯的调查摘要。原本需要数小时手动关联的工作现在只需三到四分钟即可完成。

数字证明了这一点。在整个调查中，CLUE 每个会话平均有 25 次工具调用和近 11 次查询，远远超过分析师可以合理手动执行的数量，并且精度更高。否则，每个工具调用都需要打开单独的控制台或切换到不同的界面。

然而，真正的区别在于内部环境。 CLUE通过工具直接连接到Anthropic的系统，使Claude能够访问外部安全平台永远无法访问的机构知识。当警报触发时，Claude 可以检查 Slack 以查看团队是否讨论了计划维护。它可以查询数据仓库以了解基线行为。它可以检查代码存储库以了解服务的实际用途。

### **数据治理审查**

该团队通过常见的数据治理场景展示了 CLUE 的功能：检查三个承包商在过去两个月内是否访问了他们不应该访问的任何文档。

Bow 表示，此类调查通常需要至少半天的手动工作，包括查询访问日志、交叉引用权限和审查文档分类。借助 CLUE，Claude 读取请求、制定计划并生成抽象技术复杂性的详细查询。调查只需几分钟即可结束，并生成摘要和建议，并且对每次查询运行都完全透明。

## **衡量影响**

当团队开始构建 CLUE 时，他们不仅想了解是否感觉更快，还想了解是否可以量化结果。

**误报更少**：在 CLUE Triage 之前，大约三分之一的警报被证明是误报。该比率已降至 7%，这意味着分析师将时间花在重要的信号上。\*

**覆盖范围更广**：也许比速度更重要的是团队现在可以检查的内容。在《线索》出现之前，由于根本没有时间，低置信度信号未经检查。现在，CLUE Triage 可以丰富地处理每个传入的警报，批处理可以处理数千个以前在仪表板中属于噪音的信号。

**大规模节省时间**：根据 30 天的使用情况，CLUE 自动执行了大约 12,000 个查询和 27,000 个工具调用，而手动完成的工作预计需要 1,870 小时（234 人天）。与手动分类相比，这意味着节省 5-10 倍的时间。\*

**他们仍在学习测量什么**：准确度比速度更难量化。该团队审查 CLUE 的处置并跟踪分歧，但他们仍在构建反馈循环，以了解 Claude 捕获分析师可能错过的内容的频率，反之亦然。笔录有帮助：每项调查都可以进行审核，以了解 Claude 所检查的内容以及如何得出结论。

## **我们的前进方向：让 Claude 像 Claude 一样进行调查**

AI研究中有一个概念叫做“[惨痛的教训](http://www.incompleteideas.net/IncIdeas/BitterLesson.html)“——与赋予模型通用功能并让他们找到自己的方法相比，将人类特定推理编码到模型中的观察结果始终表现不佳。 Bow 和她的团队一直在思考这对检测和响应意味着什么。

“在 CLUE 开发的早期，团队讨论了在多大程度上限制 Claude 的调查路径，”Bow 说。 “SOAR 时代的本能是：构建剧本，定义每一步，使流程具有确定性。但我们一直注意到一些事情。当我们给予 Claude 探索的自由度时（使用工具和目标，而不是严格的顺序），它经常会采取我们不会指定的调查路径。有时，这些路径会浮现我们会错过的背景。”

关键是给出 Claude 边界（它可以使用什么工具，它可以访问什么数据），同时保持策略开放。这种洞察力决定了他们下一步的线索。

**从被动到主动**：今天，CLUE 对警报做出响应。事件触发，Claude 进行调查。但该架构支持更雄心勃勃的东西：持续探索。 Claude智能体可以主动寻找可疑模式，而不是等待检测规则触发，即与团队编写的任何规则都不匹配的异常，单独看起来正常但总体来看不寻常的行为。

**向自身学习**：团队存储每一份调查记录。该语料库正在成为一个知识库 Claude，可以查询过去调查的展开模式。随着时间的推移，CLUE 会形成人类分析师无法维持的组织记忆。

**拥抱非决定论**：传统安全工具将不一致视为错误。 CLUE 将其视为一项功能。同一个警报可能会在不同的日子得到不同的调查，这很好，有时第二条路径会发现第一条路径错过的东西。该团队正在尝试并行运行多种调查策略并比较结果。

“安全运营的惨痛教训？我们花了数年时间构建编码人类调查方式的系统。下一代工具应该赋予模型调查能力，让他们找到比我们规定的更好的方法，”Bow 补充道。
