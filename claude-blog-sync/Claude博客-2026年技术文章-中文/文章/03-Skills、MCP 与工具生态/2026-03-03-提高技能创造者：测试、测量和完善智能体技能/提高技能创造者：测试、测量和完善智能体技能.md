# 提高技能创造者：测试、测量和完善智能体技能

> 发布日期：2026-03-03 · [原文链接](https://claude.com/blog/improving-skill-creator-test-measure-and-refine-agent-skills) · 机器翻译，仅供学习。

Skill-creator 现在可以帮助您编写评估、运行基准测试以及 随着模型的发展，保持您的技能发挥作用。这些更新现已在 Claude.ai 和 Cowork 中提供，作为 [Claude Code 的插件](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/skill-creator), 和 [在我们的仓库中](https://github.com/anthropics/skills/tree/main/skills/skill-creator).

自从 [启动智能体技能](https://claude.com/blog/skills) 去年十月，我们注意到大多数作者都是主题专家，而不是工程师。他们了解自己的工作流程，但没有工具来判断某项技能是否仍然适用于新的模型、在应该触发时触发，或者在编辑后是否确实有所改进。

今天，我们宣布了技能创建者增强功能，可帮助作者更有信心地进行创作。我们将软件开发的一些严格性（测试、基准测试、迭代改进）引入到技能创作中，而无需任何人编写代码。

## **两种技能**

技能一般分为两类：

**能力提升** 技能帮助 Claude 做基础模型不能做或不能始终如一地做的事情。我们的 [文档创建技能](https://github.com/anthropics/skills/tree/main/skills) 都是很好的例子。他们编码的技术和模式能够产生比单独提示更好的输出。

**编码偏好** 技能记录工作流程，其中 Claude 已经可以完成每个部分，但技能会根据团队的流程对它们进行排序。示例：一项根据既定标准完成 NDA 审查的技能，或者使用来自各个 MCP 的数据起草每周更新的技能。

这种区别很重要，因为这两种类型的技能可能出于不同的原因需要测试：

- 随着模型的提高，能力提升技能可能变得不再那么必要。评估会告诉您这种情况何时发生。
- 编码的偏好技能更持久，但其价值取决于它们对实际工作流程的保真度。评估验证保真度。

不管怎样，测试变成了一种技能 *似乎* 努力成为一个你 *知道* 作品。

## **使用评估来测试和提高技能**

Skill-creator 现在可以帮助您编写评估，这些测试用于检查 Claude 是否符合您对给定提示词的预期。如果您编写过软件测试，这会感觉很熟悉：定义一些测试提示词（如果需要还可以加上文件），描述好的外观，技能创建者会告诉您该技能是否有效。

例如，我们的 PDF 技能以前在处理不可填写的表单时遇到了困难。 Claude 必须将文本放置在精确的坐标处，没有定义的字段来引导它。 Evals 隔离了故障，我们发布了一个修复程序，将定位锚定到提取的文本坐标。

![](images/908806275805-69a237b02128b691d9e8b2af-skillscreator-pdfevals-19.png)

评估在很多方面都有帮助，但两个重要用途是捕获质量回归和了解模型进度。

首先， **捕捉质量回归。** 随着模型及其周围基础设施的发展，上个月表现良好的技能今天可能会有所不同。针对新的模型运行评估可以在某些情况发生变化之前为您提供早期信号，然后再影响您团队的工作。

第二， **了解一般模型能力何时超出您的技能。** 这主要适用于能力提升技能。如果基础模型开始通过您的评估 *没有* 加载的技能，这是该技能的技术可能已合并到模型的默认行为中的信号。技艺未断；只是不再需要了。

我们还添加了一个 **基准模式** 使用您的评估运行标准化评估。您可以在模型更新后或在迭代技能本身时运行此操作。它跟踪评估通过率、经过的时间和令牌使用情况。

![](images/00caea3c30fe-69a237f15fbc61e1ccd00a0a-skillscreator-benchmarkmo.png)

您的评估和结果会一直伴随着您。将它们存储在本地、将它们与仪表板集成或将它们插入 CI 系统。

## **通过多智能体支持进行更快、更一致的评估**

按顺序运行评估可能会很慢，并且累积上下文可能会在测试运行之间流失。技能创建者现在旋转独立的智能体来并行运行评估 **多智能体支持** ——每个都在一个干净的上下文中，有自己的令牌和计时指标。更快获得结果，无交叉污染。

我们还添加了 **比较器智能体** 对于 A/B 比较：两个技能版本，或有技能与无技能。他们在不知道哪个是哪个的情况下判断输出，因此您可以判断更改是否确实有帮助。

![](images/764771a122a9-69a74e0afa8435f070120ed9-skillscreator-ab-testing-.png)

## **让技能在正确的时间触发**

评估衡量输出质量，但只有当你的技能在应该触发的时候触发时，这才重要。随着你的技能数量增加，描述精度变得至关重要：太宽泛，你会得到错误的触发，太窄，它永远不会触发。技能创建器现在可以帮助您调整描述以实现更可靠的触发 - 它会根据示例提示词分析您当前的描述，并建议进行编辑以减少误报和漏报。

我们对文档创建技能进行了测试，发现 6 项公共技能中有 5 项的触发能力得到了改善。

![](images/7c10bab9c654-69a74e1f72940942cb534904-skillscreator-skill-descr.png)

## **展望未来**

随着模型的改进，“技能”和“规范”之间的界限可能会变得模糊。今天，SKILL.md 文件本质上是一个实施计划，提供了详细的说明，告诉 Claude *如何* 做某事。随着时间的推移，自然语言描述 *什么* 技能应该做的可能就足够了，模型会解决其余的问题。

我们今天发布的评估框架就是朝这个方向迈出的一步。评估已经描述了“什么”。最终，该描述可能就是技能本身。
